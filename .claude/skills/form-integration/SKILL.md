# Form Integration

## Purpose

Используй этот skill, когда нужно:
- создать форму на странице
- подключить отправку данных
- сделать валидацию
- реализовать success/error states
- интегрировать форму с webhook, email, CRM, Telegram или серверным обработчиком

## When to use

Используй skill в случаях:
- "сделай форму заявки"
- "подключи отправку в webhook"
- "реализуй форму обратной связи"
- "добавь валидацию формы"
- "сделай thank-you state"
- "свяжи форму с серверным обработчиком"

Используй этот skill, когда главное:
- собрать UX формы
- безопасно настроить submit flow
- описать или реализовать интеграцию

Не используй этот skill для:
- проектирования общей структуры всей страницы
- написания длинных маркетинговых текстов
- SEO-аудита страницы
- полной архитектурной переработки приложения
- общего component scaffold без формы
- релизного review всей задачи

## Inputs to analyze

Перед началом определи:
- цель формы
- минимально необходимый набор полей
- куда отправляются данные
- обязательна ли валидация на клиенте и сервере
- нужны ли маски, согласия, чекбоксы, файл-загрузка
- что должно происходить после отправки
- что считать ошибкой и как её показывать пользователю

## Instructions

1. Сначала сократи форму до необходимого минимума:
   - не добавляй поля без явной пользы
   - для первого контакта предпочитай короткие формы

2. Перед реализацией опиши:
   - какие поля будут
   - где будет валидация
   - как происходит submit
   - какой success flow
   - какой error flow

3. При реализации формы:
   - соблюдай существующие UI-паттерны проекта
   - делай понятные labels и placeholders
   - избегай двусмысленных сообщений об ошибках
   - учитывай keyboard navigation и accessibility
   - не делай client-heavy решение без необходимости

4. Для интеграции:
   - явно опиши точку отправки данных
   - не хардкодь чувствительные значения в клиентский код
   - используй безопасный серверный путь, если это требуется
   - логика интеграции должна быть понятной и проверяемой

5. Обязательно реализуй:
   - disabled state during submit
   - success state
   - error state
   - защиту от повторного клика
   - ясные сообщения пользователю

6. Если требуется согласие:
   - формулировка должна быть короткой и понятной
   - ссылка на политику должна быть предусмотрена

7. Если часть интеграции неизвестна:
   - не выдумывай endpoint или схему payload
   - предложи безопасный шаблон
   - явно пометь, что нужно уточнить

8. Если в рамках задачи были внесены изменения в код, не считай работу завершённой без проверки:
   - типов
   - линта
   - сборки
   Если какая-то проверка не запускалась, явно скажи об этом.

## Output format

1. Цель формы
2. Поля формы
3. Поток отправки
4. Какие файлы будут затронуты
5. Код
6. Что проверить руками
7. Какие данные ещё нужны для боевой интеграции
8. Какие проверки выполнены

## Quality bar

Результат должен:
- быть удобным для пользователя
- быть безопасным для интеграции
- учитывать UX отправки
- быть готовым к production после подстановки реальных endpoint / secrets
