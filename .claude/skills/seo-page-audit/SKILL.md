# SEO Page Audit

## Purpose

Используй этот skill для анализа отдельной страницы или шаблона страницы с точки зрения:
- SEO-структуры
- соответствия поисковому интенту
- качества контентной и heading-иерархии
- готовности к индексации и конверсии

## When to use

Используй skill, если задача звучит так:
- "проверь страницу на SEO"
- "оцени структуру H1-H3"
- "чего не хватает на странице услуги"
- "почему страница выглядит слабой для поиска"
- "собери SEO-рекомендации по странице"
- "проверь metadata и контентную полноту"

Используй этот skill, когда главное:
- провести аудит уже существующей страницы или структуры
- найти SEO-проблемы и точки усиления
- оценить готовность к публикации с точки зрения SEO

Не используй этот skill для:
- генерации структуры страницы с нуля
- написания полного пакета текстов
- переноса макета в код
- form integration
- финального общего release review всей задачи

## Instructions

1. Определи тип страницы:
   - главная
   - услуга
   - кейс
   - отрасль
   - о компании
   - статья
   - контакты

2. Определи основной интент страницы:
   - информационный
   - коммерческий
   - навигационный
   - брендовый
   - смешанный, если это обосновано

3. Проверь:
   - title
   - description
   - H1
   - иерархию H2/H3
   - наличие смысловых блоков
   - соответствие контента интенту
   - наличие CTA
   - наличие trust-блоков
   - избыточность или недостаточность текста
   - перелинковку
   - FAQ, если он действительно уместен
   - canonical / Open Graph, если задача про техническую часть

4. Не давай абстрактные советы.
   Каждый вывод формулируй в формате:
   - что найдено
   - почему это проблема или сильная сторона
   - что исправить

5. Не придумывай метрики, позиции или поисковые данные, если их не дали.

6. Если страница уже хорошая, всё равно укажи:
   - что уже сделано правильно
   - что можно усилить без полной переделки

## Output format

1. Общая оценка страницы
2. Что хорошо
3. Критичные проблемы
4. Средние замечания
5. Быстрые улучшения
6. Рекомендуемый вариант H1/H2 при необходимости
7. Итог: готовность страницы к публикации

## Severity model

Классифицируй замечания так:
- critical
- medium
- minor
