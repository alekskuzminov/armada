# Page From Brief

## Purpose

Используй этот skill, когда нужно превратить бриф, черновик, заметки или список тезисов в полноценную структуру страницы корпоративного сайта.

## When to use

Используй skill, если задача звучит так:
- "предложи структуру главной"
- "разложи эту страницу на блоки"
- "из брифа сделай page structure"
- "придумай состав секций под корпоративный сайт"
- "собери план страницы"
- "определи логику блоков и CTA"

Используй этот skill, когда главное:
- спроектировать page architecture
- определить состав секций
- зафиксировать логику CTA и proof-блоков
- понять, какой контент ещё нужен от пользователя

Не используй этот skill для:
- готового пакета текстов для страницы
- полной service page с черновым copy и SEO-пакетом
- черновой реализации страницы в коде
- pixel-perfect UI реализации по макету
- form integration
- SEO-аудита уже готовой страницы
- релизного review

Если пользователь просит именно service page с текстами, H1/title/description и блоками в одном ответе, предпочитай `service-page-generator`.
Если есть макет и нужна реализация, предпочитай `design-to-code`.
Если нужен только текст по уже понятной структуре, предпочитай `copy-pack`.

## Inputs to analyze

Перед началом проанализируй:
- цель страницы
- целевую аудиторию
- стадию воронки
- основной пользовательский интент
- главный CTA
- доверительные факторы
- доступные факты, кейсы, цифры, преимущества
- ограничения по тону, бренду и SEO

## Instructions

1. Сначала определи тип страницы:
   - главная
   - услуга
   - отрасль
   - кейс
   - о компании
   - контакты
   - landing page направления

2. Затем определи:
   - что пользователь хочет понять первым
   - какие возражения есть
   - где нужен proof
   - где должен быть CTA
   - какие блоки обязательны, а какие опциональны

3. Построй структуру страницы в логике:
   - первый экран
   - объяснение предложения
   - преимущества / differentiators
   - процесс / как работаем
   - trust / кейсы / цифры / клиенты / сертификаты
   - FAQ при необходимости
   - финальный CTA

4. Для каждой секции укажи:
   - цель блока
   - рекомендуемый H2
   - краткое содержание
   - рекомендуемый UI-тип блока
   - нужен ли CTA
   - нужен ли proof

5. Если задача затрагивает SEO:
   - предложи H1
   - предложи иерархию H2/H3
   - проверь, что структура соответствует одному основному интенту
   - не предлагай keyword stuffing

6. Если фактуры недостаточно:
   - не выдумывай
   - помечай элементы как шаблон / гипотеза / требуется вводная

## Output format

1. Тип страницы
2. Цель страницы
3. ЦА и основной интент
4. Рекомендуемая структура секций
5. Черновой H1 и H2
6. CTA-логика
7. Что нужно от пользователя для финализации
