# Service Page Generator

## Purpose

Используй этот skill, когда нужно быстро собрать страницу услуги для корпоративного сайта:
- по брифу
- по списку тезисов
- по черновому описанию услуги
- по конкурентному или старому тексту
- по набору преимуществ и CTA

## When to use

Используй skill, если задача звучит так:
- "подготовь service page"
- "сделай структуру и тексты для услуги"
- "дай страницу услуги с H1, блоками и CTA"
- "собери коммерческую service page"
- "подготовь основу service page под Next.js"

Используй этот skill, когда главное:
- собрать именно страницу услуги
- объединить структуру, SEO-логику и черновой copy в одном результате
- быстро получить основу для дизайна и сборки страницы

Не используй этот skill для:
- статьи в блог
- кейса
- общей главной страницы
- только формы без страницы
- чисто технического code refactor без контентной задачи
- общего page architecture без привязки к услуге
- pixel-perfect реализации по макету

Если нужна только структура страницы без готового контентного пакета, предпочитай `page-from-brief`.
Если есть макет и нужен код по дизайну, предпочитай `design-to-code`.
Если нужен только текст без структуры страницы, предпочитай `copy-pack`.

## Inputs to analyze

Перед началом определи:
- что это за услуга
- для кого она предназначена
- какой коммерческий интент у страницы
- какое действие должен сделать пользователь
- какие есть факты, кейсы, цифры, сроки, процесс, преимущества
- какие ограничения по тону и SEO
- есть ли вторичные CTA

Если в проекте существует `.claude/company-context.md`, прочитай его перед началом работы.

## Instructions

1. Начни с определения основы страницы:
   - тип услуги
   - ЦА
   - болевая точка
   - ключевое обещание страницы
   - основной CTA

2. Построй структуру страницы в логике B2B corporate service page:
   - hero / first screen
   - что входит в услугу
   - кому подходит
   - преимущества / differentiators
   - процесс работы
   - результаты / кейсы / proof
   - FAQ
   - финальный CTA

3. Для каждой секции укажи:
   - цель блока
   - рекомендуемый H2
   - краткое содержание
   - тип UI-компонента
   - нужен ли CTA
   - нужен ли proof

4. Для SEO:
   - предложи H1
   - предложи H2/H3
   - подготовь черновой title и description
   - сохрани естественность текста
   - не делай keyword stuffing

5. Для копирайтинга:
   - избегай клише
   - пиши как экспертная компания
   - не обещай неподтверждённые результаты
   - при нехватке фактуры используй безопасные формулировки

6. Для реализации:
   - предложи состав секций как компонентов
   - укажи, что можно переиспользовать
   - укажи, что будет статическим, а что потенциально CMS-driven

7. Если пользователь просит код:
   - сначала дай skeleton структуры
   - потом предложи компонентную разбивку
   - затем черновую реализацию
   - для отдельных секций или компонентов передай реализацию в `component-scaffold` или `design-to-code`

## Output format

1. Цель страницы
2. ЦА и интент
3. Рекомендуемая структура секций
4. H1 / H2 / CTA
5. Черновые тексты по блокам
6. Компонентная разбивка для Next.js
7. Что нужно уточнить для финальной версии

## Quality bar

Результат должен:
- быть пригодным для коммерческой service page
- учитывать SEO и конверсию одновременно
- быть понятным для дальнейшей передачи дизайнеру и разработчику
- не выглядеть как generic AI-текст
