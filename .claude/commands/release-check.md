Финальная проверка готовности к релизу текущей задачи или указанной страницы.

## Аргумент (опционально)
Путь к файлу или название задачи. Если аргумент не указан — проверяется текущая задача сессии.
Пример: `/release-check` или `/release-check app/services/grinding/page.tsx`.

## Алгоритм выполнения

1. **Определи область проверки:**
   - Если передан путь — прочитай указанный файл
   - Если аргумента нет — используй контекст текущей сессии

2. **Применить skill `release-check`:**
   - Структура и консистентность UI
   - Адаптив, heading hierarchy, accessibility basics
   - Metadata (title, description, Open Graph)
   - Ссылки, кнопки, CTA-логика
   - Success/error states для форм
   - Очевидные performance риски

3. **Для кода дополнительно проверить:**
   - Нет ли избыточных client components
   - Соблюдаются ли паттерны проекта из `CLAUDE.md`
   - Запускались ли `npm run type-check` и `npm run lint`

4. **Выдать результат:**
   - Статус готовности
   - Критично / нужно исправить / можно улучшить
   - Финальный checklist
   - Вердикт: можно ли выпускать
